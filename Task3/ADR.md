### <a name="_bjrr7veeh80c"></a>**Альтернативы**
Прямая интеграция с АБС:
Описание: Прямое подключение интернет-банка к API АБС без промежуточных сервисов
Недостатки:
1. Перегрузка базы данных АБС
2. Нарушение требований доступности (99,9%)
3. Сложность масштабирования
4. Высокий риск сбоев всей системы

Монолитный подход
Описание: Расширение существующего интернет-банка новым функционалом
Недостатки:
1. Усложнение поддержки монолита
2. Риск нарушения стабильности существующего функционала
3. Сложность масштабирования отдельных компонентов
4. Зависимость от подрядчика при изменениях ядра

REST API напрямую
Описание: Использование синхронных REST вызовов вместо асинхронного обмена сообщениями
Недостатки:
1. Повышенная связанность компонентов
2. Риск каскадных сбоев
3. Сложность обеспечения требуемого времени отклика
4. Проблемы с масштабированием при пиковых нагрузках


**Недостатки, ограничения, риски**

Недостатки:
1. Сложность архитектуры: Введение нескольких новых компонентов увеличивает сложность системы
2. Зависимость от Kafka: Требуется экспертиза в новой технологии для команды
3. Дополнительные точки отказа: Message Broker (kafka) как потенциальная точка сбоя
Ограничения:
1. Совместимость с текущим интернет-банком: Необходимость адаптации существующей архитектуры
2. Ограничения АБС: Вертикальное масштабирование и перегрузка базы данных
3. Регуляторные требования: Необходимость личной идентификации новых клиентов
Риски:
1. Производительность Kafka: При неправильной настройке может стать узким местом
2. Синхронизация данных: Риск рассинхронизации между системами при асинхронной обработке (конечная согласованность данных)
3. Сложность тестирования: Асинхронная архитектура усложняет end-to-end тестирование
4. Затраты на обучение: Необходимость обучения команд новым технологиям (Kafka, микросервисы)
